## The problem

Families visiting a US youth-sports organization's events ask about dining, lodging and attractions nearby. The organization wanted an assistant that answers those questions and never makes promises on its behalf.

## Constraints

- Answers must stay accurate as the information changes.
- Out-of-scope questions must be declined cleanly.
- It should be cheap and simple to run, since it's a small, low-traffic service.

## How it works

<ProjectDiagram slug="concierge-chatbot" index={0} />

The first version was a full RAG pipeline: scraping, change detection, a versioned index and a daily scheduler. Now all ~50 FAQs sit in one cached system prompt, one model call returns the route, the answer and a follow-up suggestion, and out-of-scope replies are fixed, pre-written text.

## Key decisions

1. **Know when not to use RAG.** The concierge content turned out to be only about 50 FAQs, which fits in one prompt. Removing retrieval meant fewer moving parts and no retrieval misses, and prompt caching keeps it cheap.
2. **One call per message.** A single model call decides the route, writes the answer and picks a follow-up suggestion, instead of a chain of calls.
3. **Constrain the model where it matters.** Follow-up suggestions can only come from the real FAQ list, and out-of-scope replies are fixed text, so the bot never invents a promise on the organization's behalf.

## Results

- A simpler concierge: one model call per message and no index to maintain.
- No retrieval step that can miss the right answer.
